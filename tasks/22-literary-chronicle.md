# Этап 22. Литературная хроника и жизнеописания

## Контекст
Прочитай CLAUDE.md, DESIGN.md, `data/names.ron`, `data/rules.ron` (`sim.texts`), `data/events/*.ron`, `data/hints.ron`, `crates/core/src/sim.rs` (запись хроники, `kin`), а также UI хроники, итогов года и родословной (`crates/ui`). Этапы до 21 влиты.

Владелец: «Описания событий выглядят механически. Прошедшие события нужно описывать литературно, а не "событие + цифры". Для каждого правителя хорошо бы литературно описать его правление в родословной».

Сейчас запись хроники — заголовок, шаблон без падежей («Престол наследует {ruler}.») и сдвиги осей числами. Имена не склоняются, поэтому тексты обходят косвенные падежи. Этот вопрос откладывался с этапа 09.

## Вход
main после этапа 21. Сигнатуры прошлых этапов не менять. Новые поля только с `#[serde(default)]`. Без LLM и без сети: всё детерминированно, по шаблонам из данных.

## Сделать
- **Падежи и род.**
  - Имена в `names.ron` и в пресете получают формы шести падежей. Сокращённая запись: основа плюс окончания, или полный список форм — выбери, что проще для автора данных.
  - Падежи нужны и для домов вассалов, провинций и соседей.
  - Род берётся из пола (этап 16).
  - **Шаблоны:**
    - `{ruler.род}` — падеж: им, род, дат, вин, тв, пр;
    - `{ruler:взошёл|взошла}` — согласование по роду;
    - то же для `{heir}`, `{province}`, `{neighbour}`, `{house}`.
  - Если формы нет, подставляется именительный падеж, `data_lint` предупреждает.
- **Прошедшее время для событий.**
  - У варианта события новое поле `told`: литературная запись в прошедшем времени, 1–3 предложения, с шаблонами.
  - Пример: вместо «Мятежный староста. Народ −5, стабильность −3» — «В 1214 году староста Мара поднял село на сборщиков подати; {ruler} {ruler:велел|велела} повесить зачинщиков, и в деревнях надолго затаили обиду».
  - Цифры в записи хроники и в итогах года по умолчанию скрыты. Подсказка при наведении и `trace` показывают их по-прежнему.
  - `told` напиши для всех вариантов всех событий: игрока, симуляции и войны. Если варианта без `told` нет вовсе, `data_lint` проверяет полноту.
- **Записи симуляции:** воцарение, потеря и захват земли, смерть наследника, смена закона, раздел земель, падение. Перепиши `sim.texts` литературно, с падежами и родом, по 2–3 варианта на запись. Вариант выбирается детерминированно по seed, без вызовов основного PRNG, чтобы не сдвинуть golden-тесты.
- **Жизнеописание правителя в родословной.**
  - У каждого правителя абзац 3–6 предложений.
  - **Состав:**
    - как взошёл: закон, спор, регентство;
    - прозвище по главному делу правления: Строитель, Воитель, Набожный, Собиратель земель, Тиран, Несчастный и т. п. Правила выбора прозвища в данных: по меткам решений, законам, войнам, потерям;
    - 2–3 главных события правления по важности;
    - чем кончилось: смерть, отречение, монастырь, узурпация.
  - Собирается из фраз-шаблонов в данных.
  - Показывается в родословной по клику на правителя и в «Итоге правления» основателя.
  - Прозвище используется и в хронике: «Ульрих Строитель».
- **UI:** хроника, итоги года, «Итог правления» и родословная используют новые тексты.

## Не делать
- Перевод на другие языки. LLM. Изменения механики.

## Приёмка
- Тест: склонение имени по шаблону во всех шести падежах.
- Тест: согласование по роду для правителя и правительницы.
- Тест: подстановка именительного падежа при нехватке формы и предупреждение линта.
- Тест: у каждого варианта события есть `told` (`data_lint`).
- Тест: выбор варианта текста детерминирован и не меняет основной поток PRNG (golden seed 42 без изменений по исходу).
- Тест: прозвище выбирается по правилам из данных. Строитель — по постройкам, Воитель — по войнам.
- Тест: жизнеописание собирается для правителя с отречением, со смертью и с узурпацией.
- Golden-текст хроники и жизнеописаний для seed 42. Владелец прочитает его в отчёте: приложи 2–3 жизнеописания и 10 записей хроники целиком.
- Проверка в браузере без ошибок в консоли. Скриншоты родословной с жизнеописанием в `docs/ui-22/`. Размер wasm в лимите.
