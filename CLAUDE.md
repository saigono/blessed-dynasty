# Blessed Dynasty

Стратегия на карте провинций: игрок правит только первым монархом, дальше симуляция
разыгрывает династию до падения, счёт считается по наследию. Полный дизайн в DESIGN.md.
Задачи для агентов в tasks/, порядок и запуск в tasks/README.md, статусы в трекере
(ссылка там же). Команды «работай над задачей N» и «прими задачу N» обслуживает скилл work-task.

## Структура

```
data/            RON: пресеты, карты, события, rules.ron, score.ron
crates/core/     состояние, правила, события, симуляция, хроника, счёт, PRNG. Без UI и I/O
crates/cli/      раннер, массовый прогон, трассировка
crates/ui/       egui/eframe, web и native
tasks/           задачи для агентов, одна на этап
docs/            калибровка, плейтесты
```

Зависимости только вниз: `ui` и `cli` зависят от `core`, `core` ни от кого.

## Правила кода

- Детерминизм обязателен. Свой PRNG (xoshiro256**), никаких `rand`, системного времени,
  `HashMap`-итераций в логике (только `BTreeMap`, `BTreeSet`, `Vec`). Никаких `f32`/`f64`
  в правилах: `i32` или `Fx(i64)` с масштабом 1000.
- Единица времени настраивается (`TimeUnit { ticks_per_year }`). Длительности в данных
  задаются в годах, конвертируются в тики при загрузке.
- Контент и правила в RON. Код читает схему, не содержит конкретных событий, осей,
  фракций. Оси не enum, а `BTreeMap<AxisId, Fx>` из `rules.ron`.
- Минимум кода. Нет трейтов с одной реализацией, нет абстракций «на будущее»,
  нет новых зависимостей там, где хватает пары строк.
- Каждая логическая ветка оставляет один тест, который падает, если логика сломана.
  Симуляция и партия покрываются golden-тестами: seed + решения дают известный результат.
- Код и комментарии на английском. Контент, хроника, UI на русском.

## Команды

```
cargo test --workspace
cargo build -p core --target wasm32-unknown-unknown
cargo run -p cli -- run --seed 42 --strategy neutral              # или --script data/scripts/test.ron
trunk serve crates/ui          # веб
cargo run -p ui                # нативно
```

## Правила для агентов

- Один этап, одна ветка `stage/NN`, один PR. Соседние этапы не трогать.
- Сигнатуры типов из предыдущих этапов не менять. Нужно изменить: остановись и напиши почему.
- Каждый пункт приёмки из задачи превращается в тест в `cargo test`.
- Отчёт в конце: что сделано, какие тесты добавлены, что отложено и почему, какие
  вопросы к дизайну всплыли.
