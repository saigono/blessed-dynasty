# Работа над этапами

Трекер (источник статусов): https://claude.ai/artifact/SmCxHTyYecE3DouTDo2K5Q
Коллекция `tasks`, документ = id этапа (`00`, `01`, …, `08a`, `10b`). Поля: `order`, `title`, `file`, `deps`, `status` (todo | in_progress | review | done | blocked), `branch`, `note`, `updated`.
Репозиторий: `/home/danil/code/blessed-dynasty`, основная ветка `main`. Worktree этапа: `/home/danil/code/bd-stage-<id>`, ветка `stage/<id>`.

## Режим «статус»

Фраза «статус задач» или «что по задачам»: прочитай трекер (`ArtifactData` list `tasks`, limit 50) и коротко скажи: что в работе, что на приёмке, что можно брать (todo, все `deps` в done). Ничего не меняй.

## Режим «работай над задачей»

1. Определи этап.
   - Назван номер («задача 3», «этап 08a»): id с ведущим нулём, `3` → `03`.
   - «Следующая»: прочитай трекер, возьми todo-этапы, у которых все `deps` в статусе done, и выбери минимальный `order`. Если таких нет, скажи, что именно блокирует, и остановись.
   - Трекер недоступен: done = ветки `stage/*`, влитые в main (`git branch --merged main`), in_progress = существующие worktree. Скажи, что статус взят из git.
2. Проверь, что этап не в работе: нет worktree `/home/danil/code/bd-stage-<id>` и статус не in_progress. Если worktree есть, не создавай новый: запусти агента с указанием продолжить работу в существующем.
3. Создай worktree: `git -C /home/danil/code/blessed-dynasty worktree add /home/danil/code/bd-stage-<id> -b stage/<id> main`.
4. Обнови трекер: `update` документа `tasks/<id>` с `if_version` из чтения, `status: in_progress`, `branch: stage/<id>`, `updated`: текущее время ISO.
5. Запусти агента `Agent` с `subagent_type: general-purpose`, `run_in_background: true`. Промпт собери так:

   ```
   Работай только в каталоге /home/danil/code/bd-stage-<id> (git worktree, ветка stage/<id>). Другие каталоги не трогай.
   Сначала прочитай CLAUDE.md, DESIGN.md и tasks/<file> целиком. Задача описана в tasks/<file>, выполни её полностью.
   Правила из CLAUDE.md обязательны: детерминизм, никаких float в правилах, контент в RON, минимум кода, сигнатуры прошлых этапов не менять.
   Каждый пункт приёмки из задачи превращается в тест. В конце `cargo test --workspace` должен проходить.
   Коммить на ветку stage/<id> по мере работы, последний коммит с сообщением «stage <id>: <title>». Не мержи в main.
   Если упёрся в противоречие с дизайном или нужно менять чужую сигнатуру, остановись и опиши это в отчёте вместо обходного пути.
   Отчёт в конце строго по разделам: Сделано / Тесты / Отложено и почему / Вопросы к дизайну.
   ```
6. Скажи пользователю одной строкой: этап запущен, ветка, ссылка на трекер. Не жди результата, он придёт уведомлением.
7. Когда агент завершился: в worktree выполни `cargo test --workspace` (если есть `Cargo.toml`) и `git log --oneline main..stage/<id>`. Тесты прошли и есть коммиты: трекер `status: review`, `note`: две строки сути из отчёта. Тесты упали или коммитов нет: `status: blocked`, `note`: причина. Пользователю передай отчёт агента целиком по его разделам плюс результат тестов.

## Режим «прими задачу»

Фраза «прими задачу N», «задача N принята», «мержи этап N».

1. Проверь статус в трекере: review. Иначе скажи текущий статус и спроси, точно ли мержить.
2. В основном репозитории на `main` без незакоммиченных изменений: `git merge --no-ff stage/<id> -m "merge stage <id>"`. Конфликт: не решай молча, покажи файлы и остановись.
3. `cargo test --workspace` на main. Упало: откати merge (`git reset --hard ORIG_HEAD`), статус blocked, скажи.
4. `git worktree remove /home/danil/code/bd-stage-<id>`. Ветку не удаляй.
5. Трекер: `status: done`, `updated`.
6. Скажи, какие этапы теперь разблокированы (todo с полными deps).

## Ограничения

- Один этап — один агент. Несколько разных этапов параллельно допустимы.
- Не запускай этап, у которого есть незакрытые `deps`, даже если попросили номером: скажи, что блокирует, и предложи «следующую».
- Статусы меняй только через `ArtifactData` с `if_version`. Конфликт версии: перечитай и повтори.
