# Редактор контента

Редактор — страница-артефакт на claude.ai («Редактор Blessed Dynasty»). На ней правят `data/*.ron` и прогоняют партии на правленых данных. Ядро игры работает в браузере в wasm (`crates/web-sim`), поэтому проверка и прогон дают то же, что `cli`, байт в байт. Правки хранятся в базе артефакта, Claude переносит их в репозиторий.

## Цикл правки

1. Владелец открывает артефакт, правит записи, жмёт «Проверить» и «Прогнать». Каждая правка сразу пишется в базу артефакта с автором и временем.
2. Владелец говорит Claude «примени правки из редактора».
3. Claude читает базу, переносит правки в `data/*.ron` (`scripts/editor-apply.js`) и запускает `cargo test --workspace`. Потом коммитит, удаляет перенесённые правки из базы и республикует страницу с новыми данными. Это «обнови редактор».
4. Страница открывается заново с данными нового коммита и без правок.

Скилл `.claude/skills/content-editor` ведёт Claude по шагам 3–4.

## Что на странице

- **Дерево** всех `data/**/*.ron`: файл, раздел, запись. Точка у записи — запись правлена, красная — ошибка, охра — замечание линта.
- **Запись**:
  - форма: поля по типу значения, многострочные поля для русских текстов, падежи имени из `names.ron` → `forms` рядом с полем `name`;
  - режим «RON» для сырого текста записи;
  - «Добавить копию», «Удалить», «Вернуть исходное».

  Форма переписывает запись целиком, и комментарии внутри записи пропадают. Режим RON их сохраняет.
- **Карта**: полигоны `maps/default.ron`, цвет по держателю из выбранного пресета. Клик по провинции открывает её запись.
- **Поиск** по id и тексту.
- **Проверить**: ядро загружает правленые данные (`web_sim::load`). Ошибки схемы приходят с файлом, строкой и путём к полю (`events/reign.ron:14:24: Expected integer [[0].cooldown_years]`) и показываются у поля. Замечания — те же проверки, что в `crates/core/tests/data_lint.rs` (`bd_core::lint`).
- **Прогон** в Worker, с прогрессом и отменой:
  - параметры: стратегия или все, 100–1000 партий, seed, закон с начала;
  - сводка: квартили счёта и лет, причины падения, частоты событий, скрытые узлы, критерии 08b из `docs/calibration.md`;
  - с галочкой «Сравнить» каждая стратегия играется дважды, на опубликованных и на правленых данных, и всё сводится в одну таблицу;
  - ниже — трасса и хроника одной партии.
- **Правки**: список с автором, временем и состоянием. Открыть или откатить любую.

Без `window.claude` (локально, в превью) база недоступна. Тогда правки живут в памяти вкладки, и об этом говорит плашка вверху.

## База артефакта

Коллекция `edits`, один документ на правку. Ключ документа — хеш файла, пути и операции, поэтому новая правка той же записи заменяет прежнюю.

```
{
  op:     "set" | "insert" | "delete",
  file:   "events/reign.ron",                    // путь под data/
  path:   ["id:cap_court_intrigue"],             // сегменты: f:поле, id:значение id, i:индекс, k:ключ карты
  ron:    "(\n    id: \"cap_court_intrigue\", ...)",  // set: новая запись; insert: вставляемое значение
  after:  "id:...",                              // insert: после какого элемента (нет — в конец)
  before: "(...)",                               // set: запись в опубликованных данных
  label:  "События правления › Интриги при дворе",
  author: "<user id>", at: "2026-10-03T02:18:50.033Z", base: "<коммит данных страницы>"
}
```

Текст `ron` и `before` записан без отступа самой записи. Правки применяются по порядку `at` поверх опубликованных файлов. Правка, чьей записи больше нет, показывается как «не применилась».

## Сборка и публикация

```
scripts/editor-bundle.sh
```

Скрипт собирает `web-sim` в wasm32 (release) и запускает wasm-bindgen той версии, что в `Cargo.lock`, с `--target no-modules`. Потом копирует `data/**/*.ron` в `editor/data/` и пишет `editor/data/files.json` со списком файлов и коммитом. В git лежит только `editor/index.html`, остальное генерируется.

Публикуется `editor/index.html` с файлами рядом:

- `web_sim.js`;
- `web_sim_bg.wasm`;
- `data/files.json`;
- каждый `data/<путь>.ron`.

Возможности артефакта: `db` и `user` (`scopes: ["profile"]`, чтобы показать имена авторов). Республикация идёт в тот же url, с той же картой `files`. Возможности не передаются, они сохраняются.

Wasm около 1,7 МБ, данные около 0,3 МБ. 1000 партий `neutral` в Worker идут около 21 с (нативно `cli batch` — 14 с).

## Применить правки вручную

```
node scripts/editor-apply.js edits.json            # документы коллекции edits
cargo test --workspace
```

Скрипт берёт код RON из `editor/index.html`, так что файлы выходят ровно такими, как их показывала страница. Конфликт — запись `set` на main уже не совпадает с её `before`. Такая правка пропускается, её разбирают руками или применяют с `--force`. Вставки (`insert`) не проверяются: применять каждый набор правок один раз, на чистых данных.
