# Этап 7. Счёт

## Контекст
Прочитай CLAUDE.md и DESIGN.md (раздел 8). Этап 6 завершён.

## Вход
Ветка main после этапа 6. Типы `Chronicle`, `ChronicleEntry`, `CauseTag`, `Decision`. Сигнатуры не менять.

## Сделать
- `score::compute(&Chronicle, &Decisions, &ScoreRules) -> Score { total: i64, parts: BTreeMap<String, i64>, decisive: Vec<DecisiveDecision> }`.
- Части: `years` (годы династии), `territory_years` (сумма провинций короны и вассалов по годам, по снимкам), `prestige` (накопленный по снимкам), `stability` (число кризисов с `importance` выше порога, пережитых без потери провинций), `legacy` (институты: флаги из списка `legacy_flags`, живые на момент падения).
- `data/score.ron`: веса и пороги. Стартовые веса: years 30, territory_years 1, prestige 2, stability 40, legacy 60.
- `decisive`: топ-3 решения по сумме `weight` их `CauseTag` во всех записях хроники, со знаком (положительным, если запись помечена `importance_sign: Good`, иначе отрицательным). Поле `sign` добавить в `Event` схемы этапа 2 с дефолтом `Bad`.
- Структура `Score` сериализуемая, для CLI и UI.

## Не делать
- Калибровка весов (этап 8b). Только механика.
- UI.

## Приёмка
- Тест: династия 100 лет при 10 провинциях набирает больше, чем 40 лет с пиком 20 и средним 6.
- Тест: счёт детерминирован для одной хроники.
- Тест: `decisive` содержит решение с наибольшей суммой весов меток.
