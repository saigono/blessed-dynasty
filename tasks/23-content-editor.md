# Этап 23. Редактор контента и прогоны в артефакте

## Контекст
Прочитай CLAUDE.md, DESIGN.md, `crates/core/src/data.rs` (загрузка и проверка данных), `crates/cli/src/main.rs` (`batch`), `data/` целиком (структура) и docs/calibration.md (критерии). Этапы до 22 влиты.

Владелец хочет править контент игры и запускать тестовые симуляции из claude.ai Artifact: веб-страницы с базой данных (capability `db`), которую читает и пишет Claude. Проверено (артефакт «Проба wasm», 2026-10-02, iPhone, приложение Claude): внутри артефакта работают WebAssembly из встроенных байт, из опубликованного рядом файла (`fetch` и `instantiateStreaming` с `application/wasm`) и в Worker из `blob:`. Внешние скрипты грузятся только с CDN (cdnjs, jsdelivr, unpkg), всё остальное публикуется вместе со страницей.

Схема данных ещё меняется, поэтому редактор должен быть общим, а не формой под каждую сущность.

## Вход
main после этапа 22. В `core` ничего не меняется, кроме, возможно, функции загрузки данных из набора строк вместо файловой системы, если её ещё нет. Сигнатуры не менять.

## Сделать
- **Обёртка ядра для браузера.**
  - Новый крейт `crates/web-sim`: `cdylib`, `wasm-bindgen` уже есть в зависимостях UI, новых не добавлять.
  - Функции:
    - `load(files: {path: ron_text}) -> Result<(), Vec<String>>` — загрузка с ошибками проверки данных и замечаниями `data_lint`;
    - `batch(strategy, runs, seed_start, law?) -> summary JSON` — та же сводка, что у `cli batch`, по одной функции подсчёта;
    - `trace(seed, node?) -> text`.
  - Логика сводки общая с CLI: вынести её в `core` или в общий модуль, а не дублировать. Ядро без I/O, детерминизм тот же: результат совпадает с CLI байт в байт.
- **Страница-артефакт «Редактор Blessed Dynasty»** (HTML, публикует Claude):
  - Слева дерево данных: файлы `data/*.ron` → разделы → записи. В редакторе **все** файлы данных, не только механика:
    - события и их варианты, тексты `told`, намёки (`hints.ron`), тексты хроники и жизнеописаний (`sim.texts`, прозвища);
    - имена (`names.ron`) с падежными формами и полом (этап 22);
    - страны-соседи: имя, падежи, сила, отношения, характер ИИ;
    - провинции: имя, падежи, доход, население, держатель, соседство;
    - вассальные дома;
    - пресеты: правитель, наследники, предыстория `intro`, стартовые оси и флаги;
    - законы, узлы, рёбра, оси, действия, счёт (`score.ron`), стратегии.
  - Карта: предпросмотр полигонов из `maps/*.ron` с подписями провинций и стран, цветом по держателю из выбранного пресета. Клик по провинции открывает её запись. Правка геометрии мышью не нужна: координаты правятся числами.
  - Справа редактор записи. Поля — по типу значения (число, строка, список, вложенная запись). Есть и режим сырого RON для записи. Тексты на русском — многострочные поля.
  - Поиск по id и тексту.
  - «Проверить»: ядро в wasm загружает правленые данные и показывает ошибки и замечания линта прямо у полей.
  - «Прогнать»: стратегия (или все), число партий 100–1000, seed, закон. Прогон в Worker, с прогрессом и кнопкой отмены. Сводка: медианы и квартили счёта и лет, причины падения, частоты событий, скрытые узлы, критерии 08b с отметками выполнено/нет.
  - Сравнение «до правок» и «после» в одной таблице.
- **Правки и синхронизация.**
  - Правки хранятся в базе артефакта (`db`) как набор изменённых записей с автором и временем. Исходные данные — опубликованные вместе со страницей RON-файлы текущего main.
  - Команда для Claude «примени правки из редактора»: Claude читает базу через `ArtifactData`, переносит правки в `data/*.ron`, запускает `cargo test --workspace`, коммитит и республикует страницу с новыми данными. Опиши этот процесс в `docs/content-editor.md` и в скилле `.claude/skills/` (по образцу work-task): «примени правки из редактора», «обнови редактор».
  - Скрипт `scripts/editor-bundle.sh` собирает wasm (`wasm-pack` или `cargo build --target wasm32-unknown-unknown` + `wasm-bindgen`, что уже доступно) и готовит каталог для публикации: страница, `web_sim_bg.wasm`, JS-клей, `data/*.ron`.
- **Публикацию артефакта делает координатор, не агент.** Агент готовит файлы в `editor/` и проверяет страницу локально, открыв её через `python3 -m http.server`. Страница не должна зависеть от `window.claude`: без базы правки живут в памяти страницы, и это видно в интерфейсе.

## Приёмка
- Тест: сводка `web-sim` для seed 0..99 совпадает со сводкой `cli batch` байт в байт.
- Тест: `load` возвращает ошибку схемы с путём к полю для сломанного RON.
- Тест: правка числа в одной записи меняет результат прогона, а откат возвращает прежний.
- Тест: правка имени страны или провинции попадает в загрузку и в тексты хроники с падежами.
- Локальная проверка страницы: дерево со всеми файлами `data/`, предпросмотр карты, редактор, «Проверить», «Прогнать» 100 партий без ошибок в консоли. Скриншоты в `docs/editor-23/`.
- Время 1000 партий `neutral` в браузере (Worker) записано в отчёт.
- `docs/content-editor.md` и скилл описывают цикл правки.
