# Статистика игры на GitHub Pages

Этап 11b. Игра детерминирована, и ссылка `#p=…` содержит пресет, seed и все решения. Поэтому
в конце партии игра отправляет только версию сборки, ссылку и три числа для сверки: причину
падения, годы и счёт. Остальное, от решений основателя до хроники, `cli stats` получает
повторным прогоном ссылок.

Что где лежит:

- `deploy/stats-worker/` — приёмник: `worker.js` (Cloudflare Worker), `schema.sql` (таблица
  `games` в D1), шаблон `wrangler.toml`, проверка `test.mjs`.
- `scripts/deploy.sh` — сборка с версией, адресом приёмника и счётчиком GoatCounter.
- `cli stats` — разбор выгрузки.

Без переменных сборки (`trunk serve`, `scripts/game-bundle.sh`, нативная сборка) игра ничего
не отправляет и ничего не считает, версия на стартовом экране `dev`.

## 1. GoatCounter: посещения

1. Зарегистрироваться на https://www.goatcounter.com, выбрать код сайта, например `bd`.
   Счётчик будет по адресу `https://bd.goatcounter.com`.
2. Переменная сборки: `BD_GOATCOUNTER=https://bd.goatcounter.com/count`.

`scripts/deploy.sh` с этой переменной вставляет в собранный `index.html` строку
`<script data-goatcounter="…" async src="//gc.zgo.at/count.js"></script>`. Счётчик видит
просмотры страницы и два события: `start` при новой партии и `end/<причина падения>` в её
конце (`end/NoHeir`, `end/Conquered`, `end/Usurped`, `end/NoCrownLand`, `end/Alive`). События
идут только при включённой галочке. Хвост адреса `#p=…` GoatCounter не записывает.

## 2. Cloudflare: приёмник партий

Нужен бесплатный аккаунт Cloudflare и `wrangler` (`npm i -g wrangler` или `npx wrangler`).

```
wrangler login
cd deploy/stats-worker
wrangler d1 create bd-stats
```

`d1 create` печатает `database_id`. Его и адрес игры вписать в `wrangler.toml`:

- `database_id` — из вывода выше;
- `GAME_ORIGIN` — origin игры без пути, например `https://user.github.io` для
  `https://user.github.io/blessed-dynasty/`. С другого origin приёмник отвечает 403.

Схема и выкладка:

```
wrangler d1 execute bd-stats --remote --file schema.sql
wrangler deploy
```

`wrangler deploy` печатает адрес воркера, например `https://bd-stats.user.workers.dev`.
Адрес приёмника для сборки — он же с `/game` на конце.

Приёмник принимает только `POST /game` с JSON `{version, link, fall, years, score}`: строки
`version`, `link`, `fall` и целые `years`, `score`. Тело больше 8 КБ, не JSON или с полями
не тех типов получает 400. Строка ложится в `games` с датой `datetime('now')`. Игра шлёт тело
как `text/plain`, поэтому браузер обходится без предварительного запроса OPTIONS. Проверить
воркер локально без зависимостей (нужен Node 16+): `node deploy/stats-worker/test.mjs`, это же
делает `cargo test -p cli`.

## 3. Сборка и выкладка

```
BD_STATS_URL=https://bd-stats.user.workers.dev/game \
BD_GOATCOUNTER=https://bd.goatcounter.com/count \
scripts/deploy.sh
git push origin gh-pages
```

| Переменная | Что делает | Без неё |
|---|---|---|
| `BD_VERSION` | версия сборки на стартовом экране и в статистике | `deploy.sh` берёт `git rev-parse --short HEAD` |
| `BD_STATS_URL` | адрес `POST /game`, вшивается в wasm | партии не отправляются |
| `BD_GOATCOUNTER` | адрес счётчика, скрипт вставляется в `index.html` | посещения не считаются |

Выкладывать стоит закоммиченное дерево: версия — хэш `HEAD`, и `cli stats` прогоняет ссылки
на данных этого коммита.

## 4. Выгрузка и разбор

`wrangler d1 export` выгружает только SQL. Для разбора нужен JSON:

```
cd deploy/stats-worker
wrangler d1 execute bd-stats --remote --json --command "SELECT * FROM games" > ~/games.json
```

`cli stats` читает и этот вывод (`[{"results": [...]}]`), и простой массив строк, и CSV с
заголовком: нужны столбцы `version`, `link`, `fall`, `years`, `score`, остальные не мешают.
Прогон на версии сборки:

```
git checkout <версия>
cargo run --release -p cli -- stats ~/games.json --build <версия>
```

Без `--build` берётся версия, с которой собран сам `cli` (`BD_VERSION` при сборке, иначе `dev`).
Ссылки других версий не прогоняются: на других данных они дали бы другую партию. Их число
по версиям выводится отдельно, разобрать их можно, переключившись на тот коммит.

Что печатает `cli stats`:

- число партий: всего, этой сборки, других сборок;
- `Не открылись`: ссылки, которые не декодируются или не доигрываются, с ошибкой;
- `Не сошлись с присланным`: партии, где повторный прогон дал другие причину, годы или счёт.
  Не ноль означает подделанную строку или сломанный детерминизм;
- распределение причин падения, медианы лет и счёта;
- решения основателя: сколько раз принято и в скольких партиях.

## 5. Приватность (абзац для страницы игры)

> Игра не ставит cookies и не собирает персональных данных. Если на стартовом экране
> включена галочка «Отправлять анонимную статистику», в конце партии игра отправляет версию
> сборки, ссылку на партию (стартовый seed и ваши решения, та же ссылка, что копирует кнопка
> «Скопировать ссылку»), причину падения династии, число лет и счёт. Это нужно, чтобы видеть,
> как играют, и править баланс. Посещения страницы считает GoatCounter, он тоже работает без
> cookies и не хранит IP-адреса. Снимите галочку, и партии отправляться не будут. Выбор
> запоминается в этом браузере.
