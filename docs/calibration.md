# Калибровка (этап 8b)

Как воспроизвести:

```
cargo build --release -p cli
./target/release/cli batch --runs 1000 --strategy neutral      # crown_all, vassal_all, warmonger, builder
./target/release/cli trace --seed 42 --script data/scripts/test.ron
cargo test --release -p cli -- --ignored                        # критерии и время на 1000 партий
```

Партия: основатель правит по стратегии (`neutral`: средний вариант каждого события, без
действий; остальные: `sim::AutoChooser` основателя плюс веса из `data/strategies.ron`), затем
`sim::run` и `score::compute`. Seed 0..999. Ранняя смерть: правление короче 10 лет.

## Критерии

| Критерий | Требование | До | После |
|---|---|---|---|
| Ранняя смерть на `neutral` | ≤ 10% | 6% | 6% |
| Медиана правления на `neutral` | 25–40 лет | 31 | 32 |
| Медианы счёта `vassal_all` < `crown_all` < `warmonger`, соседние | ≥ 15% | 10610 / 10742 / 25982: +1%, +142% | 10697 / 17928 / 28936: +68%, +61% |
| Доминирующие причины падения трёх стратегий | различаются | NoHeir у всех | Usurped / NoCrownLand / Alive |

## Время

1000 партий в release, одно ядро. Процессор этой машины работает на 553 МГц
(`scaling_cur_freq`; цепочка из 5 зависимых тактов идёт 9 нс). На штатных 3.6 ГГц всё будет
примерно в 6 раз быстрее.

| Прогон | Время |
|---|---|
| neutral, код и данные main | ~80 с |
| neutral, данные main, код 8b | 33 с |
| neutral, итог | 54 с |
| crown_all | 58 с |
| vassal_all | 49 с |
| warmonger | 68 с |
| builder | 59 с |

Династии стали в 2.4 раза длиннее (медиана 279 лет против 116), поэтому итог медленнее
прогона на старых данных. Что ускорено без изменения результатов (вывод batch совпадает
байт в байт): путь от столицы в `recompute_crown_power` по индексам вместо строковых ключей;
второй пересчёт силы короны после ходов соседей только если отношения сдвинулись; пересчёт
после выбора только если эффекты его касаются (`moves_crown_power`); копия мира для меток
без самих меток; ленивые цели событий; подстановка имён в текст только при наличии ключа;
`AutoChooser::action` без копий id на каждый вариант.

Тест `batch_of_a_thousand_is_fast` (ignored, release) проверяет `neutral`. `warmonger` на
этой машине 68 с.

## Что не удалось и почему

- **`Alive` как доминирующая «причина падения» у `warmonger`.** Формально критерий выполнен,
  по смыслу это династия, дожившая до горизонта в 300 лет. Сильная армия и земли основателя
  делают падение редким: узурпация 19%. Без изменения кода можно было бы двигать
  `max_years`, но тогда падают все, и у трёх стратегий снова одна причина (Usurped).
- **`crown_all` и `builder` почти не отличаются от `neutral`.** Основатель правит около 35 лет
  из 280; дальше у всех один и тот же автомат. Различие держится на том, что основатель
  оставил: розданные земли (`vassal_all`) или завоёванные (`warmonger`). Политика
  «держать всё» почти совпадает с базовым поведением, критерий их не требует.
- **Автомат слишком рационален.** Он всегда берёт самый безопасный вариант, поэтому до
  калибровки ни одна стратегия не падала иначе, чем без наследника. Падения разных типов
  появились, только когда я уменьшил страх риска (`usurped`, `secede`). Это калибровка
  характера автомата, а не мира.
- **Модель наследников.** Наследники не умирают от старости, на трон идёт старший брат или
  сестра, рождения зависят только от возраста правителя. Падения без наследника я убрал
  таблицей рождений, но после раннего отречения ребёнок-правитель держит династию на
  регентстве, пока не подрастёт (наблюдение 10b). Без правки кода этого не исправить.
- **Сила соседей не восстанавливается.** Её меняют только войны и дань, поэтому за 300 лет
  соседи слабеют, и `warmonger` быстро упирается в предел. Нужен параметр роста силы (код).
- **60 с на одном ядре** на этой машине выполняются для `neutral` (54 с), но не для
  `warmonger` (68 с). Причина в частоте процессора, см. «Время».
